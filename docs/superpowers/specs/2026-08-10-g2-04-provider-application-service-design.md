# G2-04 Provider 应用服务设计

## 目标

将 Provider 的配置、加密凭证、运行时客户端和凭证池收敛到单一应用服务，使创建、更新、独立 Key 更新、启用/禁用和删除具备失败补偿，不产生孤儿配置、孤儿凭证或新旧客户端混用。

## 边界

- 保持现有 FastAPI 路径、请求字段和响应主体兼容。
- 保持 `webui_overrides.json` 与 `provider_<id>.key` 存储格式兼容。
- 独立 Key 更新接口纳入同一事务服务。
- G2-04 继续使用现有路由引用检查；完整引用收集属于 G2-05。
- 审计、发现缓存失效和 WebSocket 广播是提交后副作用，不参与事务回滚。
- 不引入数据库，不迁移现有 Provider 数据。

## 组件

### ProviderRepository

封装 `models.providers.<pid>` 的读取、创建、更新、删除和恢复。删除失败必须恢复 `ConfigService` 内存状态；应用服务只通过该接口修改 Provider 配置。

### ProviderCredentialStore

负责读取明文 Key、生成加密候选内容、保存旧文件快照、原子发布新 Key、删除 Key 和恢复旧文件。临时文件与正式文件位于同一目录，发布使用原子替换。

### ProviderRuntimeRegistry

负责构建候选安全客户端、获取当前客户端、原子替换或移除客户端、同步凭证池以及关闭不再使用的客户端。候选客户端在提交失败时关闭；旧客户端仅在整个事务成功后关闭。

### ProviderApplicationService

按 Provider ID 使用进程内异步锁串行化操作。它协调三类组件，保存操作前快照，按固定顺序提交，并在异常时逆序补偿。

## 事务

### 创建

1. 确认 Provider 不存在并构建候选客户端。
2. 准备加密凭证候选。
3. 保存配置。
4. 原子发布凭证。
5. 发布运行时客户端并替换凭证池。
6. 成功后返回；失败时恢复为空状态并关闭候选客户端。

### 更新与独立 Key 更新

1. 快照旧配置、旧凭证文件、旧客户端和旧凭证池。
2. 使用新配置与最终 Key 构建候选客户端；禁用操作不构建客户端。
3. 保存新配置。
4. 必要时原子发布新 Key。
5. 原子替换或移除运行时客户端和凭证池。
6. 成功后关闭旧客户端；失败时恢复四态并关闭候选客户端。

### 删除

1. Router 完成当前引用检查。
2. 快照四态并先从运行时阻止新调用。
3. 删除配置与凭证，移除凭证池。
4. 成功后关闭旧客户端。
5. 任一步失败时恢复配置、凭证、客户端和凭证池。

## 错误处理

- 保留 G2-01 稳定错误协议，不返回 Key、密文、文件内容或上游正文。
- 输入错误继续由 Router 返回 4xx。
- 应用服务事务失败返回稳定的 Provider 操作失败错误，并保留原异常为服务端 cause。
- 回滚失败记录错误日志，但不得覆盖原始事务异常。

## 并发与生命周期

- 同一 Provider 的 mutation 串行执行，不同 Provider 可并行。
- 旧客户端只在成功提交后关闭。
- 候选客户端只要未成为最终运行时状态，就必须关闭。
- `enabled=false` 立即移除运行时客户端和凭证池，但保留配置与加密 Key。
- `enabled=true` 使用保留 Key 构建并发布新客户端。

## 测试

- 创建、更新、Key 更新、禁用、启用和删除均执行故障注入。
- 每个失败点断言配置、Key、运行时客户端和凭证池与操作前一致。
- 覆盖旧客户端与候选客户端关闭、同 ID 并发串行、API 兼容和发现缓存/广播行为。
- 运行 G2-04 专项、G2-01 至 G2-03 回归、完整后端、Ruff、compileall、版本同步、前端构建和 `git diff --check`。
