# 移动端架构重构验收矩阵 v2

## 1. 使用规则

- `P0`：不通过则禁止进入下一阶段或发布。
- `P1`：发布候选前必须通过。
- `P2`：允许记录有期限的例外，但必须有负责人。
- 每项证据必须包含命令、退出码、摘要和产物路径。
- “人工看起来正常”不能替代可自动化的验收。

证据记录格式：

```text
验收 ID：
日期：
提交：
环境：
命令/步骤：
期望：
实际：
产物：
结论：PASS | FAIL | EXCEPTION
负责人：
例外到期日：
```

### RET-007 详细步骤

2. 记录四类向量表行数和旧维度。
3. 使用 Mock Embedding 执行确定性迁移。
4. 使用测试远程 Provider 执行小规模真实协议迁移，不调用付费生产密钥。

8. 在 10%、50%、90% 三个阶段注入失败。
9. 验证原库哈希和可读性不变。

### PRV-004 详细场景

- 连接阶段异步解析全部 A/AAAA 记录，并在拨号前完成地址分类。
- 非管理员授权目标的任一 DNS 结果命中回环、私网、链路本地或元数据地址时，整次连接拒绝。
- 真实 TCP listener 集成测试确认 hostname 只解析一次，实际套接字只连接已校验 pinned IP。
- HTTP Host Header 和 TLS SNI、证书 hostname 校验继续使用原 Provider hostname。
- discover、probe 和 chat 共用同一安全客户端入口，不允许 SDK 独立二次解析。
- 同 origin 重定向可继续，跨 scheme、hostname 或 effective port 的重定向在发起下一跳前拒绝并关闭响应。
- `PROVIDER_ALLOW_HOSTS` 仅授权明确的 Provider hostname；通用 `SSRF_ALLOW_HOSTS` 不产生 Provider 权限。
- 明文 HTTP 仅允许显式授权且全部解析为非公网地址的目标，并受 `PROVIDER_ALLOWED_HTTP_PORTS` 限制。

## 12. 性能验收

预算在 G0 基线测量后冻结，至少记录：

- Android 冷启动 P50/P95。
- WebUI 首屏可交互时间。
- Chat 1000 条消息滚动帧率。
- 动态壁纸下内存和帧率。
- 终端持续输出 CPU、内存和丢帧。
- Dashboard/Knowledge Graph 降级前后指标。
- 后台 10 分钟后的内存与连接状态。

发布标准：新版本不得相对冻结基线产生未批准的显著回退。

## 14. 最终签署

发布候选必须由以下角色或责任域确认：

- 架构/实现负责人：架构边界与代码一致。
- 后端负责人：Provider、迁移、终端协议通过。
- 前端负责人：全部路由和移动 UI 通过。
- Android 负责人：系统壳、安全和生命周期通过。
- 发布负责人：构建、签名、回滚和制品通过。
- 安全负责人：出站、密钥、WebView 和终端边界通过。
- 法务/渠道负责人：仅在包含 Termux runtime 时必需。
